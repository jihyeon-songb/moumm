# Evals

Moumm 단서 추출이 "맞혔다"고 볼 기준과 점수 기록.

- 정답 데이터: `fixtures/phase0/samples.json` (캡션 원문은 `fixtures/phase0/private/captions.json`, git 제외)
- 실행: `pnpm eval:clues`

## 필드 정의

기준은 `lib/clues/schema.ts`(설계 문서 7장)다. 스키마에 없는 필드는 평가하지 않는다.

### 게시물 단위

| 필드 | 스키마 키 | 뜻 | 정답 라벨 (`samples.json`) | 측정 |
| --- | --- | --- | --- | --- |
| 범위 판정 | `is_place_content` | 맛집·카페를 소개하는 게시물인가 | `kind`가 `out_of_scope`가 아니면 true | 정확도 |
| 협찬 여부 | `is_sponsored` | 협찬·광고 표기 true, "내돈내산" false, 언급 없음 null. 모델이 아니라 키워드로 판정 (`sponsorship.ts`) | `sponsored` | 정확도 |

### 장소 단위 (`places[]`)

| 필드 | 스키마 키 | 뜻 | 정답 라벨 | 측정 |
| --- | --- | --- | --- | --- |
| 장소명 | `name` | 상호. 지점명은 뺀다 | `places[].name` | 정확도·재현율 |
| 지점명 | `branch_hint` | "본점", "망원점" 등 게시물에 적힌 지점 표현 | `places[].branch` (추가 필요) | 정확도 |
| 지역 표현 | `region_hint` | 게시물에 적힌 지역 표현 그대로 ("상무지구") | `places[].regionHint` | 정확도 |
| 행정구역 | `region_normalized` | 시·구 단위 ("광주 서구") | 없음 (카카오 주소에서 계산 가능) | 채움률 |
| 주소 | `address` | **게시물에 적힌** 주소 | `places[].addressInPost` (추가 필요) | 정확도 |
| 대표 메뉴 | `menus[]` | 메뉴명과 가격(원, 없으면 null) | `places[].inCaption.menus` (추가 필요) | 놓침률·지어냄률 |
| 추천 이유 | `reason` | 게시물이 추천하는 이유 한 문장 | `places[].inCaption.reason` (추가 필요) | 놓침률·지어냄률 |
| 방문 팁 | `tips[]` | 웨이팅, 주차, 유아의자, 예약, 휴무 등 | `places[].inCaption.tips` (추가 필요) | 놓침률·지어냄률 |
| 영업시간 | `hours_mentioned` | 게시물에 적힌 영업시간 그대로 | `places[].inCaption.hours` (추가 필요) | 놓침률·지어냄률 |

- `samples.json`의 `places[].address`는 **카카오 장소의 실제 주소**(매칭 정답)다. 추출 필드 `address`(게시물에 적힌 주소)와 뜻이 달라서 그대로 비교하지 않는다.
- 서술형 4개 필드(메뉴·추천 이유·방문 팁·영업시간)는 내용을 받아 적지 않고, 캡션에 그 정보가 **있는지(true)/없는지(false)만** 라벨링한다. 내용이 맞는지는 `--verbose` 결과를 사람이 훑어서 확인한다.

라벨 형식 (장소 하나):

```json
{
  "name": "가짜식당",
  "branch": "본점",
  "regionHint": "상무지구",
  "addressInPost": null,
  "inCaption": { "menus": true, "reason": true, "tips": false, "hours": false },
  "address": "카카오 장소 주소",
  "kakaoPlaceId": "...",
  "verified": true
}
```

### 평가하지 않는 것

- **카테고리**: 추출하지 않는다. 장소 매칭 후 카카오 로컬 API가 준다 (설계 문서 8장).
- **가격대**: 별도 필드가 아니다. 필요하면 `menus[].price`에서 계산한다.

### 값의 출처

지금 수집하는 것은 공개 메타 태그뿐이라 출처는 세 가지다. 댓글과 위치태그는 수집하지 않는다.

| 출처 | `clueSource` 값 | 수집 경로 | 현재 추출 여부 |
| --- | --- | --- | --- |
| 캡션 | `caption` | `og:description` | 추출함 |
| 커버 이미지 글자 | `cover_image` | `og:image` OCR | 아직 없음 (`ImageOcr` 미구현) |
| 캐러셀 이미지 글자 | `carousel_image` | `img_index` 이미지 OCR | 아직 없음 |

- OCR이 없는 동안 모델 출력은 모두 캡션에서 나온 값이다. 그래서 출처는 값마다가 아니라 샘플의 `clueSource`로 기록한다. 설계 문서의 `evidence`(필드별 근거)는 OCR을 붙일 때 스키마에 추가한다.
- `clueSource`가 `caption`이 아닌 샘플은 장소명을 찾을 수 없는 게 정상이고, 캡션에 없는 장소를 지어내지 않았는지만 본다 (`score.ts` 현재 동작).

## 채점 규칙

### 공통

- **정규화**: 비교 전에 공백을 모두 지우고 영문은 소문자로 바꾼다 (`score.ts`의 `norm`).
- **빈값**: 정답이 `null`(정보 없음)이면 예측도 `null`이어야 맞다. 정답이 `null`인데 값을 내면 지어냄으로 센다.
- **장소 단위 필드는 이름이 맞은 장소만 채점한다.** 이름을 못 찾은 장소는 장소명에서 이미 틀렸으므로 다른 필드에서 또 감점하지 않는다.

### 게시물 단위

| 필드 | 맞음 |
| --- | --- |
| 범위 판정 | `is_place_content`가 정답과 같다 |
| 협찬 여부 | `is_sponsored`가 정답(true / false / null)과 같다 |
| **샘플 통과** | 범위 판정이 맞고, 정답 장소를 모두 찾고, 정답에 없는 장소를 내지 않았다 |

### 장소 단위

| 필드 | 맞음 | 예 |
| --- | --- | --- |
| 장소명 | 정규화 후 같거나, 한쪽이 다른 쪽을 포함한다 | "8번식당 본점" ↔ "8번식당" 맞음 |
| 지점명 | 정규화 후 같거나 포함한다. 둘 다 `null`이면 맞음 | "대구본점" ↔ "본점" 맞음 |
| 지역 표현 | 정규화 후 같거나 포함한다. 둘 다 `null`이면 맞음 | "상무지구" ↔ "상무" 맞음 |
| 주소 | 시·구·동(또는 도로명)까지 같다. 번지·층·호수는 보지 않는다. "광주광역시"와 "광주"는 같게 본다 | "광주 서구 마륵복개로 57" ↔ "광주광역시 서구 마륵복개로" 맞음 |
| 서술형 4개 | 정답 `true`일 때 값이 있으면(배열은 1개 이상) 맞음, 비면 **놓침**. 정답 `false`일 때 비면 맞음, 값이 있으면 **지어냄** | |

### 집계

- **장소명 재현율** = 찾은 정답 장소 수 / 전체 정답 장소 수
- **장소명 정밀도** = 정답과 맞은 예측 장소 수 / 전체 예측 장소 수
- **샘플 통과율** = 통과 샘플 수 / 전체 샘플 수. 장소가 많은 샘플 하나가 재현율을 끌어올릴 수 있어서 (baseline의 s09) 재현율과 함께 본다.
- **유형별 통과율**: `kind`·유형 태그별로 따로 낸다.
- **놓침률** = 놓침 수 / 정답 `true` 수, **지어냄률** = 지어냄 수 / 정답 `false` 수 (필드별)
- 통과 기준(목표치)은 정하지 않고 기록만 한다. 다음 주 LLM 버전끼리 비교할 때 정한다.

### 애매한 케이스

| 상황 | 라벨링 규칙 |
| --- | --- |
| 한 게시물에 장소 여러 곳 | 캡션이 **방문·추천 대상으로 소개한** 장소를 모두 정답에 넣는다. 순서는 보지 않는다. 장소마다 필드 라벨을 따로 단다 |
| 비교·언급만 된 장소 ("OO보다 낫다", "옆집 OO") | 정답에 넣지 않는다. 모델이 내면 "정답에 없음"으로 센다 |
| 장소명이 이미지에만 있음 | 장소는 정답에 넣고(OCR 대비) `clueSource`를 `cover_image`/`carousel_image`로 둔다. 캡션에 이름이 나오는 장소만 `captionPlaces`에 적는다 |
| 정보 없음 | 해당 필드를 `null` 또는 `inCaption.*: false`로 둔다. 모델이 비우면 맞음 |
| 체인, 지점 모름 | `kind: "chain"`, `branch: null`. 상호만 맞으면 장소명 정답 |
| 범위 밖 | 음식점·카페·주점·베이커리를 소개하지 않으면 `kind: "out_of_scope"`, `places: []`. 밀키트·레시피·식품 광고·숙소·관광지가 여기에 들어간다 |
| 협찬 | 캡션 문구로만 판단한다. "협찬/광고/제공받아" → true, "내돈내산" → false, 언급 없음 → null |

## Baseline

LLM 점수를 해석하기 위한 기준선. 앱에서는 쓰지 않는다. 실행: `pnpm eval:clues --baseline` (API 키 불필요)

- 규칙 (`lib/clues/baseline.ts`): 줄 맨 앞의 `📍` `📌` `🏠` `상호:` `가게명:` `매장명:` 뒤 텍스트를 장소명으로 쓴다. `/ | , (` 앞까지만 자르고, 주소처럼 보이면 버린다. 표지가 하나도 없으면 장소 게시물이 아니라고 판정한다.
- 장소명 외 필드는 비워 둔다. 협찬 여부만 LLM 추출과 같은 키워드 판정을 쓴다.
- 규칙은 고치지 않는다. 기준선이 움직이면 LLM 점수와 비교할 수 없다. 바꿔야 하면 `BASELINE_VERSION`을 올리고 점수 기록에 새 줄로 남긴다.
