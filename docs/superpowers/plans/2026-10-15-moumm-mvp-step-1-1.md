# Moumm MVP 1-1 개발 계획 — 링크 하나로 장소 1곳 저장까지

- 작성일: 2026-10-15
- 기준: `docs/superpowers/specs/2026-10-13-moumm-mvp-design.md` (v2) 13장 1-1 단계
- 상태: 착수 전 검토

## 목표

인스타그램 링크를 붙여넣으면 캡션을 읽고, 장소 1곳을 찾아 확인받고, 결과 화면을 보여주고, 브라우저에 저장하는 한 줄을 끝까지 만든다.

```
링크 입력 → 정규화 → 캡션 수집 → LLM 단서 추출 → 카카오 검색·순위화 → 장소 확인 → 결과 화면 → 로컬 저장
```

## 이번 단계에서 하지 않는 것

| 항목 | 단계 |
| --- | --- |
| 여러 곳 목록, 체인 지점 목록, 범위 밖 안내 화면 | 1-2 (단, LLM 스키마와 판정 값은 1-1부터 받아 둔다) |
| 이미지 OCR, 캡션 붙여넣기, 직접 검색 | 1-3 (장소 확인의 "다른 장소 검색"은 1-1에 포함) |
| Supabase 캐시와 이벤트 저장 | 1-3 (1-1은 이벤트를 콘솔 로그로만 남김) |

## 완료 조건

- Phase 0 샘플 중 장소 1곳짜리 6개(다도해물나라, 장군닭발, 이현김밥, 원화소복, 나랑가, 코끼리생막창)가 링크 입력부터 저장까지 동작한다.
- 6개 모두 장소 확인 화면에서 정답이 1위 후보로 나온다.
- 링크 입력부터 장소 확인 화면까지 5초 안 (p90, 배포 환경 기준).
- 단위 테스트와 E2E 1개가 통과한다.

## 작업 목록

### 0. 프로젝트 셋업 (0.5일) — 완료 2026-10-19

- 저장소 루트에 Next.js(App Router) + TypeScript 앱 생성. `spikes/`는 그대로 둔다.
- 테스트: Vitest(단위), Playwright(E2E)
- 스키마 검증: zod
- 환경 변수: `KAKAO_REST_API_KEY`, `GEMINI_API_KEY`, (선택) `ANTHROPIC_API_KEY` — `.env.example`에 키 이름만 기록
- Vercel 배포, 함수 지역 `icn1`
- 폴더 구조

```
app/
  page.tsx                 홈 (링크 입력)
  confirm/page.tsx         장소 확인
  result/page.tsx          결과 화면
  saved/page.tsx           가볼 곳
  api/analyze/route.ts     분석 API
lib/
  source/normalize.ts      SourceNormalizer
  meta/fetch.ts            MetaFetcher
  clues/extract.ts         ClueExtractor (LLM)
  clues/schema.ts          출력 스키마 (zod)
  places/kakao.ts          KakaoPlaceProvider
  places/rank.ts           CandidateRanker
  storage/saved.ts         브라우저 저장
fixtures/phase0/           Phase 0 샘플 13개 (캡션, 정답 라벨, 카카오 응답 기록)
```

### 1. Phase 0 고정 데이터 만들기 (0.5일) — 완료 2026-10-20

- `fixtures/phase0/samples.json`: 링크, 유형, 캡션 원문, 정답 장소(상호·주소·카카오 장소 ID), 기대 결과(한 곳 / 여러 곳 / 체인 / 범위 밖)
- 측정 시트 `docs/phase0/moumm-phase0-spike.xlsx`의 라벨을 옮긴다.
- 이후 모든 테스트와 LLM 평가가 이 파일을 기준으로 돈다.

### 2. SourceNormalizer (0.5일) — 완료 2026-10-20

- `spikes/og-probe/lib/probe.js`의 `normalize`를 TypeScript로 옮긴다.
- 테스트도 함께 옮긴다: 13개 샘플, `/계정명/p/`, `img_index`, `reels`·`tv`, 잘못된 도메인.

### 3. MetaFetcher (0.5일) — 완료 2026-10-20

- `og-probe`의 `readMeta`, `captionFrom`, 요청 로직을 옮긴다.
- 모바일 브라우저 UA로 요청 → 캡션이 없거나 로그인 페이지면 크롤러 UA로 1회 재시도.
- 인스타그램 도메인만 요청한다.
- 테스트: 저장해 둔 HTML 고정 데이터로 파싱 검증 (네트워크 없이).

### 4. ClueExtractor (1.5일)

- 설계 문서 7장 스키마를 zod로 정의한다. `is_place_content`, `places[]`, `is_sponsored`까지 1-1에서 받는다.
- 프롬프트: 캡션에 적힌 것만 추출하고 추측 금지. 지역 힌트는 원문과 행정구역 둘 다.
- 형식 검증 실패 시 2회까지 재시도.
- **평가 스크립트** `npm run eval:clues`: `fixtures/phase0/samples.json` 13개를 돌려 상호·지역·장소 수·범위 밖 판정이 정답과 맞는지 표로 출력한다. 프롬프트를 고칠 때마다 이걸 돌린다.
- 목표: 장소 1곳짜리 6개에서 상호 6/6, 범위 밖 1/1 판정.

### 5. KakaoPlaceProvider (1일)

- 키워드 검색: `category_group_code`로 음식점(FD6)·카페(CE7)만. 이 파라미터는 값을 하나만 받으므로 두 번 호출해서 합친다.
- 주소 검색.
- 테스트: 실제 응답을 한 번 기록해 `fixtures/phase0/kakao/`에 저장하고, 테스트는 기록된 응답으로 돈다.

### 6. CandidateRanker (1일)

- 설계 문서 8장 규칙 1~5를 구현한다. 규칙 6의 체인 판정은 값만 계산하고 화면은 1-2에서.
- 장소 하나당 "상호만", "지역어 + 상호", (주소가 있으면) "주소" 검색 → 합치기 → 주소 근사 비교 → 순위.
- 회귀 테스트: 장군닭발(지역 붙이면 놓침), 나랑가(협동조합 1위), 이현김밥(26-1 vs 26).

### 7. 분석 API `POST /api/analyze` (0.5일)

- 입력: `{ url }` → 출력: `{ source, clues, candidates[], status }`
- `status`: `ok` / `no_clue` / `out_of_scope` / `multi_place` / `fetch_failed` — 1-1 화면은 `ok`만 정상 처리하고 나머지는 "아직 지원하지 않는 게시물" 안내.
- 같은 URL 동시 요청은 하나로 합친다 (메모리 잠금).
- 단계별 소요 시간을 로그로 남긴다 (5초 목표 확인용).

### 8. 화면 (2일)

- 홈: 링크 입력, "장소 찾기", 진행 상태 2단계.
- 장소 확인: 후보 2~3개, "이 장소가 맞나요?", "다른 장소 검색"(카카오 키워드 검색 입력).
- 결과 화면: 설계 문서 4.4 순서. 게시물 정보(추천 이유, 메뉴·가격, 방문 팁, 협찬)와 카카오 정보(주소, 전화) 출처 구분. 영업시간은 "카카오에서 보기" 링크 + 캡션 언급 시 "게시물에서 언급". 외부 지도 버튼 3개.
- 가볼 곳: 목록, 상태 변경, 원본 링크 열기.
- 모바일 우선, 375px 기준.

### 9. 브라우저 저장 (0.5일)

- localStorage, 읽기·쓰기 모두 try/catch. 실패하면 "저장되지 않았어요" + 재시도.
- 같은 장소를 다른 링크로 저장하면 원본 링크를 추가한다.
- 첫 저장 시 저장 위치 안내 (Safari 장기 미방문, 인앱 브라우저).

### 10. E2E와 배포 확인 (0.5일)

- Playwright: 링크 입력 → 장소 확인 → 결과 → 저장 → 가볼 곳에서 확인. 외부 API는 고정 데이터로 대체.
- 배포 환경에서 6개 샘플을 직접 넣어 보고 소요 시간 기록.

## 일정 (하루 4~5시간 기준)

| 주차 | 작업 |
| --- | --- |
| 1주차 | 0 셋업, 1 고정 데이터, 2 정규화, 3 메타 수집, 4 단서 추출 |
| 2주차 | 5 카카오, 6 순위화, 7 API, 8 화면 시작 |
| 3주차 초 | 8 화면 마무리, 9 저장, 10 E2E·배포 |

약 9.5일. 4번(LLM 프롬프트)과 8번(화면)이 가장 늘어나기 쉽다.
