# Moumm MVP — SNS 맛집·카페 방문 판단 정보 통합

- 상태: 대화에서 설계 승인됨
- 작성일: 2026-10-13
- 기준 문서: [MVP SNS Notion](https://app.notion.com/p/MVP-SNS-3f30cc9b23208128a741f008932159d0?source=copy_link)

## 1. 요약

Moumm은 인스타그램에서 발견한 맛집·카페가 실제로 가볼 만한 곳인지 한 화면에서 판단하도록 돕는 모바일 웹 MVP다. 사용자가 인스타그램 게시물 또는 릴스 링크를 붙여넣으면 시스템이 장소를 자동으로 찾아 후보를 제시하고, 사용자가 확인하거나 수정한 뒤 메뉴·가격·위치·영업시간·추천 이유를 모아 보여준다.

링크만으로 정보를 충분히 얻지 못하면 사용자가 캡션을 붙여넣거나, 직접 장소를 검색하거나, 본인이 가진 영상·화면 녹화를 올려 분석할 수 있다. 자동 분석이 실패하더라도 사용자가 장소를 직접 찾아 저장할 수 있어야 한다.

첫 버전은 국내 맛집·카페에 한정한다. 그러나 장소 데이터와 검색 제공자를 분리하여 추후 Google Places 같은 해외 제공자를 추가할 때 화면과 저장 구조를 다시 만들지 않도록 한다.

## 2. 문제, 가설, 성공의 정의

### 문제

사용자는 인스타그램에서 장소를 발견한 뒤 메뉴, 가격, 후기, 위치, 영업시간을 확인하려고 네이버·카카오·구글 지도 등을 다시 검색한다. 이 과정에서 게시물을 잊거나 검색을 포기하고, 저장해 둔 게시물도 실제 방문으로 이어지지 않는다.

### 제품 가설

게시물에서 추출한 추천 맥락과 지도 제공자의 장소 정보를 한 화면에 모으면 사용자의 추가 검색을 줄이고, 저장 또는 관심 없음이라는 결정을 더 빠르게 만들 수 있다.

### 1차 검증 기준

약 10명의 사용자가 최근 본 인스타그램 맛집·카페 콘텐츠로 테스트한다.

- 10건 중 7건 이상에서 사용자가 직접 장소를 바꾸지 않고 올바른 장소 후보를 얻는다.
- 10건 중 8건 이상에서 사용자가 저장 또는 관심 없음으로 판단을 끝낸다.
- 10건 중 6건 이상에서 외부 추가 검색 없이 방문 여부를 결정한다.
- 링크 흐름과 영상 흐름이 모두 중단 없이 완료된다.
- 잘못 찾은 장소는 사용자가 언제든 수정할 수 있다.
- 업로드한 원본 영상은 처리 후 삭제되며, 안전 정리 기한인 24시간을 넘기지 않는다.

외부 지도 열기는 그 자체로 실패가 아니다. 메뉴 확인, 후기 확인, 길찾기 등 연 이유를 함께 기록해 부족한 정보를 구분한다.

## 3. 범위

### MVP에 포함

- 인스타그램 게시물·릴스 URL 입력 및 정규화
- 이전에 확인된 동일 링크의 장소 즉시 조회
- 새 링크에 대한 공개 메타데이터 기반 최선의 자동 분석
- 링크 분석 실패 시 캡션 붙여넣기, 영상 업로드, 직접 장소 검색
- 최대 60초, 최대 100MB의 MP4·MOV 영상 분석
- 장소 후보 2~3개 제시, 확인 및 수정
- 장소명, 주소/지역, 카테고리, 외부 지도 링크 표시
- 확보된 경우 대표 메뉴, 언급 가격, 추천 이유, 영업시간, 평점·후기 정보 표시
- 브라우저에 가볼 곳 저장, 관심 없음, 방문 완료 상태 저장
- 원본 인스타그램 링크와 저장 장소 연결
- 익명 사용자의 장소 확인·수정 결과를 공유 매핑 품질 개선에 활용
- 분석 및 의사결정 이벤트 기록

### MVP에서 제외

- 회원가입, 로그인, 여러 기기 간 동기화
- 팔로우, 피드, 댓글 등 소셜 기능
- 개인화 추천, 알림, 예약, 리뷰 작성
- 맛집·카페 외 카테고리
- 인스타그램 외 SNS 자동 수집
- 네이티브 앱과 인스타그램 공유 메뉴 연동
- 해외 장소 검색의 실제 출시
- 복잡한 지도 탐색이나 챗봇
- 사용자의 계정으로 인스타그램에 로그인하는 비공식 수집 방식

## 4. 사용자 경험과 화면

### 4.1 홈

한 가지 행동에 집중한다.

- 제목: “마음에 든 장소, 바로 확인해 보세요”
- 인스타그램 링크 입력창
- 기본 버튼: “장소 찾기”
- 보조 버튼: “영상으로 찾아보기”
- 하단 이동: 홈 / 가볼 곳

링크 입력이 기본 경로이고 영상 업로드는 링크에서 장소를 찾기 어려운 경우의 보조 경로다.

### 4.2 분석 진행

사용자가 현재 단계를 이해하도록 상태를 순서대로 보여준다.

1. 링크 또는 영상 확인
2. 콘텐츠 분석
3. 장소 검색
4. 후보 준비

분석은 비동기로 실행한다. 새로고침하거나 잠시 화면을 닫아도 작업 ID로 진행 상태를 다시 확인할 수 있다. 같은 입력의 중복 작업은 만들지 않는다.

### 4.3 장소 확인

가능성이 높은 후보 2~3개를 장소명, 지역, 카테고리와 함께 보여준다. 사용자는 다음 중 하나를 선택한다.

- 후보가 맞다고 확인
- 다른 후보 선택
- “다른 장소 검색”으로 직접 검색
- “여기에 없어요” 선택

후보가 하나뿐이어도 반드시 “이 장소가 맞나요?”를 보여주며 자동 결과를 확정 사실처럼 취급하지 않는다.

### 4.4 판단 결과

결정에 필요한 정보를 위에서부터 배치한다.

- 대표 이미지(제공 가능한 경우)
- 장소명, 지역, 카테고리
- 장소 일치 신뢰도와 “장소 변경”
- 오늘의 영업시간(확보된 경우)
- 가격대 또는 영상에서 언급된 가격(확보된 경우)
- “영상/게시물에서 추천한 이유”
- 대표 메뉴 태그
- 외부 지도에서 보기
- “가볼 곳 저장” / “관심 없음”

장소명, 주소/지역, 카테고리, 외부 지도 링크는 항상 제공한다. 영업시간, 가격, 평점, 후기처럼 확보하지 못한 정보는 추측하지 않고 “정보 없음”으로 표시한다.

### 4.5 가볼 곳

로그인 없이 현재 브라우저에 저장한 장소를 보여준다.

- 가볼 곳과 방문 완료 상태
- 장소 핵심 정보
- 처음 발견한 인스타그램 링크
- 외부 지도 열기

브라우저 데이터 삭제나 기기 변경 시 목록이 사라질 수 있음을 설정 또는 첫 저장 시 짧게 안내한다.

## 5. 핵심 사용자 흐름

### 링크 흐름

1. 사용자가 인스타그램 URL을 붙여넣는다.
2. 서버가 URL을 정규화하고 플랫폼 식별자 또는 해시를 만든다.
3. 확인된 공유 매핑이 있으면 즉시 장소를 반환한다.
4. 매핑이 없으면 공개적으로 접근 가능한 메타데이터를 최선의 범위에서 분석한다.
5. 텍스트 단서로 장소 후보를 검색하고 순위를 매긴다.
6. 사용자가 장소를 확인하거나 수정한다.
7. 시스템이 판단 정보를 보여주고 사용자는 저장 또는 관심 없음을 선택한다.

### 링크 정보가 부족한 흐름

1. 시스템이 링크에서 충분한 단서를 얻지 못했음을 설명한다.
2. 사용자는 영상 업로드, 캡션 붙여넣기, 직접 검색 중 하나를 선택한다.
3. 선택한 입력을 분석하거나 검색한다.
4. 이후 장소 확인과 판단 결과 흐름은 동일하다.

### 영상 흐름

1. 사용자가 본인이 보유한 MP4 또는 MOV 파일을 선택한다.
2. 앱이 형식, 길이 60초 이하, 크기 100MB 이하를 업로드 전에 검사한다.
3. 개인정보 처리와 원본 삭제 시점을 알리고 동의를 받는다.
4. 서버가 임시 저장하고 비동기 분석 작업을 만든다.
5. 장면 표본, 화면 글자, 음성을 분석해 장소 단서를 구조화한다.
6. 장소 후보를 검색하고 사용자가 확인하거나 수정한다.
7. 성공·실패와 관계없이 처리 종료 후 원본을 삭제한다. 예외 상황에서도 24시간 이내 정리한다.

영상 입력에 원래 인스타그램 링크가 함께 있으면 확인된 장소를 해당 링크와 연결한다. 링크 없이 영상만 올린 경우에는 장소 판단과 로컬 저장은 가능하지만 공유 링크 매핑은 만들지 않는다.

## 6. 시스템 구성

### 권장 기술 구성

- 모바일 웹: Next.js, TypeScript
- 서버 API: Next.js 서버 영역의 BFF/API
- 공유 데이터: Supabase Postgres
- 임시 영상: Supabase Storage의 비공개 버킷 또는 동일한 수명 주기 정책을 지원하는 임시 저장소
- 비동기 분석: 작업 큐 인터페이스 뒤의 별도 영상 분석 워커
- 개인 목록: 브라우저 localStorage 또는 IndexedDB

초기 배포 환경에 맞춰 큐나 워커 제품은 바꿀 수 있으나, API 요청 안에서 긴 영상 분석을 끝내도록 만들지는 않는다.

### 주요 컴포넌트

1. `SourceNormalizer`
   - 인스타그램 URL에서 추적 매개변수를 제거하고 게시물/릴스 식별자를 얻는다.
   - 서버 저장용 안정적인 해시를 만든다.
2. `SourceAnalyzer`
   - 공개 메타데이터, 사용자 제공 캡션 또는 영상 분석 결과를 동일한 구조의 단서로 변환한다.
3. `VideoAnalysisWorker`
   - 장면 변화 기반 프레임 표본 추출
   - OCR로 자막, 간판, 메뉴판 읽기
   - 오디오 추출과 음성 전사
   - 단서를 합쳐 장소명, 지역, 메뉴, 가격, 추천 이유 후보 생성
4. `PlaceProvider`
   - 키워드/지역 검색, 상세 조회, 외부 지도 URL 생성을 제공하는 공통 인터페이스
5. `CandidateRanker`
   - 장소명, 지역, 카테고리, 메뉴 단서의 일치도를 합쳐 후보 순위를 만든다.
6. `MatchService`
   - 과거 공유 매핑 조회, 사용자 확인·수정 이력 추가, 신뢰 상태 갱신
7. `DecisionView`
   - 확보된 정보만 일관된 형식으로 표시하고 저장/관심 없음 결정을 기록한다.

### 데이터 흐름

`사용자 입력 → 정규화/검증 → 기존 매핑 조회 → 분석 작업 → 장소 후보 검색·순위화 → 사용자 확인/수정 → 판단 정보 조회 → 로컬 저장 + 익명 이벤트 기록`

기존 매핑이 신뢰 가능한 경우 분석 작업을 건너뛴다. 다만 사용자는 결과 화면에서 언제든 장소를 바꿀 수 있다.

## 7. 콘텐츠 분석 원칙

### 인스타그램 링크

임의의 공개 게시물 URL 내용을 공식 API만으로 항상 읽을 수 있다고 가정하지 않는다. MVP의 핵심 경로를 비공식 로그인 세션, 우회 수집, 깨지기 쉬운 HTML 스크래핑에 의존시키지 않는다.

- 공개적으로 제공되는 메타데이터만 최선의 범위에서 사용한다.
- 정보가 없거나 접근이 제한되면 즉시 사용자 제공 입력으로 전환한다.
- 캡션 원문이나 영상 원본을 공유 매핑의 영구 데이터로 저장하지 않는다.
- 동일 URL은 정규화 식별자 또는 해시로 조회해 재분석 비용을 줄인다.

### AI 구조화 출력

AI 응답은 자유 문장이 아니라 검증 가능한 스키마를 사용한다.

- 추정 장소명 목록
- 추정 지역/주소 단서
- 음식·카페 카테고리
- 언급 메뉴와 가격
- 추천 이유 요약
- 각 단서의 근거 유형: 화면 글자, 음성, 캡션, 메타데이터
- 전체 추출 신뢰도

필수 형식 검증에 실패하면 제한 횟수만 다시 시도하고, 이후에는 직접 검색으로 안내한다. AI가 만든 영업시간, 평점, 주소를 사실 데이터로 사용하지 않는다. 이 정보는 장소 제공자의 검색 결과에서만 가져온다.

## 8. 장소 제공자와 해외 확장

### 국내 MVP

국내 장소 검색은 `KakaoPlaceProvider`를 우선 구현한다. 카카오 로컬 키워드 검색 결과에서 장소 식별자, 이름, 카테고리, 주소, 좌표, 전화번호, 장소 상세 링크를 가져온다. 영업시간·메뉴·후기처럼 API에서 안정적으로 제공되지 않는 정보는 억지로 채우지 않고 “정보 없음”과 외부 지도 링크를 제공한다.

동적 정보는 영구 복제하지 않고 짧게 캐시하거나 결과 화면 진입 시 다시 확인한다. 장소 제공자의 이용약관과 저장·표시 정책을 준수한다.

### 해외 확장

`PlaceProvider` 인터페이스에 `GooglePlaceProvider`를 추가하고 국가 또는 지역에 따라 제공자를 선택한다. 화면, 분석 결과, 저장 목록은 같은 표준 장소 모델을 사용한다.

표준 장소 모델은 다음을 포함한다.

- 내부 `placeId`
- 국가 코드
- 현지어 장소명과 주소
- 카테고리
- 위도·경도
- 외부 지도 링크
- 시간대와 통화(해외 기능 출시 시 활성화)
- 제공자별 식별자를 연결하는 별도 목록

카카오나 구글의 식별자를 앱의 유일한 장소 키로 사용하지 않는다. 한 장소에 여러 제공자 식별자를 연결할 수 있어야 한다. 이 구조로 국내에서 저장한 흐름을 유지한 채 해외 장소 제공자만 추가할 수 있다.

## 9. 데이터 모델과 저장 정책

### 서버 데이터

#### `sources`

- `id`
- `platform`: MVP에서는 `instagram`
- `source_type`: `post` 또는 `reel`
- `normalized_key_hash`
- `created_at`

정규화된 원본 URL 자체 대신 해시를 기본 조회 키로 사용한다.

#### `places`

- `id`: 앱 내부 식별자
- `country_code`
- `name`, `category`, `address`
- `latitude`, `longitude`
- `map_url`
- `refreshed_at`

#### `place_sources`

- `place_id`
- `provider`
- `provider_place_id`
- `last_verified_at`

#### `source_place_matches`

- `id`, `source_id`, `place_id`
- `status`: `unverified`, `user_confirmed`, `high_confidence`
- `ai_confidence`
- `confirmation_count`, `correction_count`
- 최소한의 `extraction_summary`
- `created_at`, `updated_at`

#### `match_revisions`

- `id`, `match_id`
- 익명 기기 식별자의 해시
- 이전/제안 장소 식별자
- `action`: 확인 또는 수정
- `created_at`

수정은 기존 값을 덮어쓰지 않고 이력으로 추가한다. 여러 확인과 수정 비율을 바탕으로 현재 매핑의 신뢰 상태를 다시 계산한다.

#### `analysis_jobs`

- `id`, 선택적 `source_id`
- `input_type`: link, caption, video
- `input_fingerprint`: 중복 방지용 해시
- `status`: queued, analyzing, searching, needs_confirmation, completed, failed
- `failure_code`
- `created_at`, `completed_at`, `expires_at`

#### `events`

- 익명 세션/기기 식별자의 해시
- 이벤트 이름
- 선택적 source/place/job 식별자
- 최소한의 메타데이터
- `created_at`

### 브라우저 데이터

개인 저장 목록은 서버 계정 없이 브라우저에 보관한다.

- 내부 장소 식별자와 화면 표시용 최소 스냅샷
- 사용자가 입력한 원본 인스타그램 URL
- 저장 시각
- 상태: 가볼 곳 또는 방문 완료

원본 인스타그램 URL은 개인 브라우저 저장 목록에서만 유지한다. 공유 서버에는 정규화 키의 해시와 장소 매핑만 둔다.

### 개인정보와 보안

- 영상 업로드 전에 분석 목적, 임시 저장, 삭제 시점을 명확히 알린다.
- 영상 버킷은 비공개이며 짧은 수명의 서명된 업로드/조회 권한만 사용한다.
- 분석이 끝나거나 실패하면 원본 영상을 즉시 삭제하고, 누락된 파일은 24시간 이내 자동 정리한다.
- 캡션 원문, 전체 전사문, 영상 프레임은 영구 저장하지 않는다.
- 공유 매핑은 서버 API를 통해서만 수정하며 직접 DB 쓰기를 노출하지 않는다.
- 익명 쓰기 API에 요청 제한, 입력 검증, 중복 방지를 적용한다.
- 로그에 원본 영상 URL, 서명 토큰, 전체 캡션을 남기지 않는다.

## 10. 오류와 복구

- 잘못된 URL: 입력값을 유지하고 유효한 인스타그램 게시물·릴스 URL 형식을 안내한다.
- 링크 정보 부족: 영상 업로드, 캡션 붙여넣기, 직접 검색을 제시한다.
- 잘못된 영상: 업로드 전에 MP4/MOV, 60초, 100MB 제한을 구체적으로 알려준다.
- 분석 지연: 단계별 진행 상태와 재개 가능한 작업 ID를 제공한다.
- 장소 후보가 여러 개: 상위 2~3개와 직접 검색, 해당 없음 선택지를 제공한다.
- 공유 매핑이 틀림: 사용자의 수정을 이력으로 추가하고 신뢰도를 다시 계산한다.
- AI 또는 장소 제공자 일시 실패: 제한적으로 재시도한 뒤 직접 검색을 제공한다.
- 일부 정보 없음: “정보 없음”을 표시하고 외부 지도 버튼을 유지한다.
- 브라우저 저장 실패: 저장되지 않았음을 명확히 알리고 재시도할 수 있게 한다.

핵심 원칙은 자동 분석 실패가 수동 장소 저장을 막지 않는다는 것이다.

## 11. 이벤트와 측정

다음 이벤트를 최소한으로 기록한다.

- `link_submitted`
- `cached_match_found`
- `analysis_started`, `analysis_completed`, `analysis_failed`
- `video_uploaded`, `video_analysis_completed`, `video_analysis_failed`, `video_deleted`
- `caption_fallback_used`, `manual_search_used`
- `place_matched`, `place_match_corrected`
- `place_saved`, `decision_not_interested`
- `external_map_opened`: 메뉴, 후기, 길찾기, 기타 사유 포함
- `visit_marked`

이벤트로 자동 일치율, 수정률, 저장률, 결과 화면 체류 시간, 외부 추가 검색 비율, 방문 완료율을 계산한다. 사용자별 행동 추적보다 MVP 가설 검증에 필요한 집계값을 우선한다.

## 12. 테스트와 완료 조건

### 자동 테스트

- URL 정규화: 게시물/릴스, 추적 매개변수, 잘못된 도메인, 중복 URL
- AI 스키마 검증: 누락 필드, 잘못된 타입, 낮은 신뢰도, 재시도 종료
- 후보 순위: 장소명·지역·메뉴 단서 조합과 동점 처리
- 공유 매핑: 확인·수정 이력, 신뢰 상태 갱신, 잘못된 캐시 무효화
- 로컬 저장: 저장, 관심 없음, 방문 완료, 원본 링크 유지
- 분석 작업: 중복 방지, 상태 전이, 재개, 실패 코드
- 장소 제공자 장애와 제한 응답
- 영상 삭제: 성공, 실패, 만료 정리 모두 검증
- 모바일 E2E: 링크 입력부터 저장까지, 영상 업로드부터 저장까지, 수동 검색 복구

### 기능 완료 조건

- 링크 정규화와 기존 매핑 즉시 조회가 동작한다.
- 새 링크 자동 분석 및 세 가지 대체 경로가 동작한다.
- 최대 60초 영상의 비동기 분석과 진행 상태 복구가 동작한다.
- 장소 확인·수정 후 판단 정보를 보여준다.
- 사용자가 로그인 없이 장소를 저장하고 방문 상태를 바꿀 수 있다.
- 원본 링크와 외부 지도 링크를 다시 열 수 있다.
- 공유 매핑과 분석 이벤트가 개인정보 원칙에 맞게 기록된다.
- 원본 영상 삭제가 자동화되고 검증된다.
- 앞의 1차 검증 기준을 10명 테스트에서 측정할 수 있다.

## 13. 단계별 출시

### 1단계: 국내 모바일 웹 MVP

복사한 인스타그램 링크를 붙여넣는 A안으로 출시한다. 링크 분석, 영상/캡션/직접 검색 대체 경로, 사용자 장소 확인, 로컬 저장, 카카오 장소 검색을 제공한다.

### 2단계: 공유 메뉴 연결

MVP에서 사용성을 검증한 뒤 네이티브 앱 또는 공유 확장을 추가한다. 사용자가 인스타그램 공유 메뉴에서 Moumm을 고르면 URL이 현재의 링크 분석 진입점으로 전달된다. 분석·확인·저장 흐름은 그대로 재사용하므로 핵심 서버를 다시 만들지 않는다.

### 3단계: 해외 맛집·카페

국가/지역 라우팅과 `GooglePlaceProvider`를 활성화하고 시간대, 통화, 현지어 주소 표시를 추가한다. 표준 장소 모델과 기존 확인 UI는 유지한다.

### 후속 판단 항목

실사용 데이터로 다음을 결정한다.

- 공유 확장이 링크 붙여넣기보다 충분히 큰 전환 개선을 만드는지
- 영상 분석 비용 대비 자동 일치율 개선이 충분한지
- 사용자가 가장 자주 외부 지도를 여는 이유가 무엇인지
- 로그인과 기기 간 동기화가 실제 저장 유지 문제를 해결할 만큼 필요한지

## 14. 확정된 제품 원칙

- 자동 추출 뒤 사용자 확인·수정을 반드시 거친다.
- 틀린 정보보다 빈 정보를 선택하며, 없는 정보는 만들지 않는다.
- 비공식 인스타그램 수집을 제품의 필수 기반으로 삼지 않는다.
- 동일 링크의 확인 결과는 안전한 공유 매핑으로 재사용한다.
- 개인 저장 목록과 원본 링크는 로그인 없이 사용자 브라우저에 둔다.
- 원본 영상은 임시 처리 후 삭제한다.
- 국내 MVP를 만들되 장소 제공자와 내부 장소 모델은 해외 확장을 막지 않게 설계한다.
- 네이티브 공유 연동은 나중에 추가하되 현재 링크 분석 흐름을 그대로 사용한다.
